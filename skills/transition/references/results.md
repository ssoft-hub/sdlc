# Anomalies, problems and defects

## Acts of this situation

Accepting work with a known nonconformity, or closing a problem without resolution, is an act of the
quality assurance process. Leaving an acceptance problem unresolved is an act of the acts table of
`references/acceptance.md`.

## Managing transition results

Outcomes served: ready for operation.

| Subject | What the agent does |
|---|---|
| Anomalies | should name each anomaly by its source - the strategy, the enabling systems, the execution of transition, the system definition |
| Own work | should take the corrective actions within its own work where the release interacts inconsistently with its environment or the enabling systems of utilization |
| Accepted output | should propose by "Defect" the changes of an accepted output, the requirements included, where the release interacts inconsistently with its environment or the enabling systems of utilization |
| Root cause | should leave the root cause analysis, the corrective actions on the process and the lessons to the project assessment and control process |
| Problems | shall record the incidents and problems met in delivery and installation, report each to those responsible for resolving it, and ensure that it is resolved, unless a decision leaves it unresolved |
| Their resolution | should leave problem resolution to the quality assurance and project assessment and control processes, and the changes of the requirements, architecture, design or elements to the other technical processes |
| Defect | shall name a defect found in transition, with the outputs it affects, and, where that output is accepted, pass a change request to the process that owns that output, which decides it |
| Repetition | shall repeat the affected steps of transition after the correction |
