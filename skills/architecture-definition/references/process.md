# The architecture definition process

| Name | Statement | Observable as |
|---|---|---|
| purpose | system architecture alternatives are generated, one or more that frame the stakeholder concerns and meet the system requirements are selected and expressed in a set of consistent views, the allocation of the system requirements to the elements of the system is defined, and the software is given a design that can be implemented and verified against its requirements; the process iterates with business or mission analysis, stakeholder needs and requirements definition and requirements definition, and its outcomes serve the life cycle processes | - |
| concerns addressed | the architecture addresses the defined stakeholder concerns | each key concern named with the architectural entities and the views that address it, and the evaluation of the selected candidate against the concerns recorded |
| viewpoints developed | architecture viewpoints are developed | the viewpoints and model kinds recorded with the justification of their selection, or the project's conventions of architecture description serving as them |
| context defined | the context, the boundaries and the external interfaces of the system are defined | the external entities and the interfaces and interactions crossing the boundary recorded |
| views developed | architecture views and models of the system are developed | the models and views recorded and consistent with each other |
| concepts allocated | the concepts, properties, characteristics, behaviours, functions and constraints significant to architecture decisions are allocated to architectural entities | the allocation recorded |
| elements defined | the system elements and their interfaces are defined | the system elements, their relationships to the architectural entities and their internal and external interfaces recorded |
| candidates evaluated | architecture candidates are evaluated | the evaluation of each candidate against the constraints, the requirements and the criteria recorded, with the rationale of the selection |
| baseline achieved | an architecture baseline is achieved for the processes of the life cycle | the baseline of the selected architecture under configuration management and communicated to the parties that work to it |
| aligned with the requirements | the architecture is aligned with the requirements and the design characteristics | every requirement allocated, the elements allocated to design characteristics, the principles of design and evolution recorded, and every discrepancy of the work with the accepted architecture named |
| enabling systems available | the enabling systems or services architecture definition needs are available | access obtained to each enabling system planned |
| traceability developed | traceability of the architecture elements to the stakeholder requirements and the system requirements is developed | the traceability record |
