# The architecture of a software item

A software component is a part of a software item that its architecture singles out.

## Relating the architecture to design

Outcomes served: context defined, views developed, concepts allocated, elements defined, baseline
achieved, aligned with the requirements.

| Subject | What the agent does |
|---|---|
| Top-level structure | shall transform the requirements of the software item into an architecture that describes its top-level structure and identifies its main software components, allocate all the requirements of the item to the components and refine them for detailed design, and record the architecture |
| Main components | should take as main software components, for example, data storage and access to it, the communication mechanism, the business logic and the user interface |
| Basis | should make the architecture the basis for verifying the software items, combining them and integrating them with the rest of the system |
| Interfaces | shall develop and record a top-level design of the external interfaces of the software item and of the interfaces between it and its components |
| Database | shall develop and record a top-level design of the database, where the item has one |
| User documentation | shall develop and record preliminary versions of the user documentation |
| Tests and integration | shall define and record the preliminary test requirements and the software integration schedule |

## Evaluating architecture candidates

Outcomes served: candidates evaluated.

| Subject | What the agent does |
|---|---|
| Correctness and testability | shall analyse the architecture of the software item and its interface and database designs for correctness and testability, so that the components can be built and tested |
| Evaluation | shall evaluate the architecture of the software item and its interface and database designs for traceability to the requirements of the item, external consistency with those requirements, internal consistency between the components, appropriateness of the design methods and standards, feasibility of detailed design, and feasibility of operation and maintenance |
| Results | shall record the results of the evaluation |
| Reviews | shall have the architecture of the software item pass a technical review, which the verification process conducts, and a management review, which the project assessment and control process conducts |
