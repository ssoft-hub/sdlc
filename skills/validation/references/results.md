# Problems and nonconformities

## Acts of this situation

| Act | An explicit request does not decide it while | Tasks still due on an explicit request |
|---|---|---|
| leaving a problem unresolved, or a nonconformity not eliminated, or accepting a product with it | - | Problems; Results of `SKILL.md` |

## Managing validation results

Outcomes served: results recorded, evidence provided.

| Subject | What the agent does |
|---|---|
| Anomalies | should name each anomaly by its source - the validation strategy, the enabling systems, the execution, the system definition -, leaving the root cause analysis, the corrective actions, the improvements and the lessons to the project assessment and control process |
| Problems | shall record the incidents and problems, and pass the problems and nonconformities to problem resolution, so that each is resolved and each nonconformity eliminated |
| Nonconformity | shall name a nonconformity with the need left unconfirmed and the outputs it affects, and, where that output is accepted, propose the correction as a change request to the process that owns that output and wait for that process's decision before the output changes |
| Repetition | shall repeat the affected validation actions after the correction |

Problem resolution is left to the quality assurance and project assessment and control processes,
and the changes of the requirements, architecture, design or elements to the other technical
processes.
