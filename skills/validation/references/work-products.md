# Work products of validation

The outcomes are those `references/process.md` names. "This process" as a source is validation at
another of its steps. The acquirer and the other stakeholders are parties, not processes: the plan
directs the reports to them, the results are made available to them, and they accept the validation.

## Inputs

| Work product | Outcomes it serves | Source |
|---|---|---|
| the requirement specification | evidence provided | the stakeholder needs and requirements definition process; the system/software requirements definition process |
| the stakeholder requirements | criteria defined, evidence provided | the stakeholder needs and requirements definition process |
| the acceptance criteria | criteria defined | the stakeholder needs and requirements definition process |
| the quality policy | validation performed | the quality management process |
| the quality plan | validation performed | the quality assurance process |
| the quality criteria | criteria defined | the quality management process; the quality assurance process |
| the system | validation performed, evidence provided | the verification process; the transition process, for the installed system in its operational environment |
| the traceability record | validation performed, evidence provided | the stakeholder needs and requirements definition process; the system/software requirements definition process |
| the corrective action register | validation performed, results recorded, evidence provided | the quality assurance process |
| the tracking system | validation performed, results recorded, evidence provided | the infrastructure management process |
| the problem record | results recorded | this process |

## Outputs

| Work product | Outcomes it serves | Receiver |
|---|---|---|
| the quality criteria | criteria defined | the quality assurance process |
| the validation strategy: the validation methods, techniques and tools | validation performed | the configuration management process, for the baseline |
| the validation test plan: the approach to performing the tests | validation performed | the project planning process, which integrates the tasks of the process into the project plans |
| the validation constraints | constraints identified | the stakeholder needs and requirements definition process |
| the infrastructure requirements, for the enabling systems of the process | enabling systems available | the infrastructure management process |
| the quality record | criteria defined, validation performed | the quality assurance process |
| the validation results: the validation checklist | validation performed, results recorded, evidence provided | the acquirer and the other stakeholders; the quality assurance process; the transition process, for the readiness review |
| the problem record | results recorded | the quality assurance process, for problem resolution |
| the change request | validation performed, results recorded | the configuration management process; the stakeholder needs and requirements definition process; the system/software requirements definition process |
| the communication record | results recorded, evidence provided | the acquirer and the other stakeholders |
| the configuration item: the baseline, the validation strategy | evidence provided | the configuration management process |
