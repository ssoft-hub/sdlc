# Feedback on the accepted architecture and requirements

Taking or changing an architecture decision is an act of the architecture definition process.
Baselining or changing accepted system or software requirements is an act of the system/software
requirements definition process. This situation produces the change request each of them receives.

## Acts of this situation

| Act | An explicit request does not decide it while | Tasks still due on an explicit request |
|---|---|---|
| a change to the architecture or the requirements that the design requires | - | Unachievable |

## The design and the architecture

Outcomes served: characteristics defined.

| Step | What the agent does |
|---|---|
| Basis | should base the design on the requirements as the architecture and the feasibility analyses explored them |
| Division | should make the design answer for the compatibility of the elements and the feasibility of building and integrating them, the architecture answering for suitability, viability and the desired results |

## Design characteristics and design enablers of each element

Outcomes served: characteristics defined.

| Step | What the agent does |
|---|---|
| Unachievable | shall name a characteristic that cannot be achieved without reworking the accepted architecture or an accepted requirement as a defect of an accepted output, with the outputs it affects, and pass a change request to the process that owns that output - the architecture definition or the system/software requirements definition process -, which decides it |
| Allocation | should give architecture definition the feedback that confirms or consolidates the allocation to the elements |

## Managing the design

Outcomes served: traceability established.

| Step | What the agent does |
|---|---|
| Changing elements | should give architecture definition, through the traceability of the detailed design characteristics to the architectural entities, the feedback on changing elements for architectural characteristics: modularity, usability, interoperability, protection |
