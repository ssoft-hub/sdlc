# Alternatives for obtaining an element

## Acts of this situation

| Act | An explicit request does not decide it while | Tasks still due on an explicit request |
|---|---|---|
| the selection of the preferred alternative for obtaining an element when it is bought, licensed or taken from the acquirer | the decision contradicts the accepted architecture (its entities, interfaces, principles of design and evolution), a requirement or a constraint; a characteristic is not achievable with it | Evaluation, for the alternative named alone |

## Evaluating alternatives for obtaining system elements

Outcomes served: characteristics defined.

| Step | What the agent does |
|---|---|
| Evaluation | shall evaluate each non-developmental item, each new design alternative and a design decision a request names against criteria derived from the expected design characteristics or the requirements of the element, for its suitability for the intended application |
| Preferred | shall determine the preferred alternative for the element |
| Support | should apply system analysis or evaluations, and decision management, to the selection and the studies |
