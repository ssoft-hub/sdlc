# Technologies and design enablers of an element

A design enabler is a model, an algorithm, a calculation, a formal expression, a parameter value, a
pattern or a heuristic the design characteristics rest on.

## Acts of this situation

| Act | An explicit request does not decide it while | Tasks still due on an explicit request |
|---|---|---|
| the choice of a technology for an element that the accepted architecture and the project's rules do not yet admit | the decision contradicts the accepted architecture (its entities, interfaces, principles of design and evolution), a requirement or a constraint; a characteristic is not achievable with it | Technologies; Evaluation of `references/obtaining.md` |

## Preparing for design definition

Outcomes served: characteristics defined.

| Step | What the agent does |
|---|---|
| Technologies | shall define the technologies each element needs: a language, a platform, an off-the-shelf component, a storage |
| Several technologies | should provide for an element that needs several technologies, such as software and operator roles |
| Their range | should consider all the applicable technologies and the contribution of each to the system solution |

## Design characteristics and design enablers of each element

Outcomes served: enablers selected.

| Step | What the agent does |
|---|---|
| Choice of enablers | should define or select the design enablers considering compatibility, affordability, safety and the other critical properties in the planned operational environment, and human-centred design |
