# The design definition process

| Name | Statement | Observable as |
|---|---|---|
| purpose | data and information on the system and its elements are provided in enough detail to enable an implementation consistent with the architectural entities as the models and views of the system architecture define them; for software, a design is provided that can be implemented, verified against the requirements and the software architecture, and detailed for coding and testing | - |
| characteristics defined | the design characteristics of each system element are defined | the design characteristics of each element recorded with their representation and limits, and the technologies each element needs |
| requirements allocated | the system requirements are allocated to the system elements | the allocation of every requirement to the elements recorded, down to the software units |
| enablers selected | the necessary design enablers are selected or defined | the models, algorithms, patterns and other enablers the characteristics rest on recorded |
| interfaces defined | the interfaces between the system elements are defined or refined | the interfaces of each element recorded in enough detail to implement them without further information |
| artifacts developed | design artifacts are developed | the design artifacts in the form the implementation technology requires, with the design rationale; under the baseline where the project keeps one |
| enabling systems available | the enabling systems or services design definition needs are available | access obtained to each enabling system planned |
| traceability established | traceability of the design characteristics to the architectural entities of the system architecture is established | the traceability record between the design, the requirements and the architectural entities |
