# An anomaly, a problem or a defect found

## Acts of this situation

| Act | An explicit request does not decide it while | Tasks still due on an explicit request |
|---|---|---|
| leaving a nonconformity found not eliminated, or accepting a product with it, conditional acceptance on the results of a technical review included | an action that has not been performed or completed, or whose result cannot be observed, is called not performed, with the reason, and not passed | Problems; Outcome of `references/technical-reviews.md` |

Where the participants of a technical review decide its conditional acceptance, the agent shall take
an explicit request as that decision only where the participants have agreed it.

## Managing verification results

Outcomes served: report made.

| Subject | What the agent does |
|---|---|
| Anomalies | should name each anomaly by its source - the verification itself, the enabling systems, the execution, the system definition -, leaving the root cause analysis, the corrective actions, the improvements and the lessons to the project assessment and control process |
| Problems | shall record the incidents and problems, and pass the problems and nonconformities found to problem resolution, so that each is resolved and each nonconformity eliminated |
| Defect | shall name a defect found, with the outputs it affects, and, where that output is accepted, pass a change request to the process that owns that output, which decides it |
| Repetition | shall repeat the affected verification actions after the correction |

Problem resolution is left to the quality assurance and project assessment and control processes,
and the changes of the requirements, architecture, design or elements to the other technical
processes.
