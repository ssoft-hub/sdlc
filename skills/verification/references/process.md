# The verification process

| Name | Statement | Observable as |
|---|---|---|
| purpose | objective evidence is provided that a system element or the system fulfils its specified requirements and has its specified characteristics: each software work product and service reflects the specified requirements, the implementation of each system and software requirement is tested for compliance, and the system is ready for delivery; technical reviews give the stakeholders a common understanding of the state of the project's products; the anomalies - errors, defects, faults - of any information item, implemented element or process are identified, and information is provided for the decision on them | - |
| constraints identified | the verification constraints that influence the requirements, the architecture or the design are identified | the constraints recorded and passed to the system/software requirements definition, architecture definition and design definition processes |
| enabling inputs identified | the inputs for the requirements for the enabling systems of verification are identified | the enabling systems planned and the inputs for their requirements identified |
| enabling systems available | the enabling systems or services verification needs are available | access obtained to each enabling system planned |
| element verified | the system or the system element has passed verification | the results of each verification action performed recorded against its criteria, each requirement in scope reported as passed, failed or not performed |
| report made | a report containing information for corrective actions is made | each anomaly, defect and problem recorded with its source and passed to its resolution, and the results available to the stakeholders |
| evidence provided | objective evidence that the realized system fulfils the requirements, the architecture and the design is provided | the records of the procedures performed, their results compared with the expected ones |
| traceability established | traceability of the verified elements is established | the traceability record between the verified elements, the verification strategy, the architecture, the design and the system requirements |
