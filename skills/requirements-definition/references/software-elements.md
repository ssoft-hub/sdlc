# Requirements for software elements

## Defining system requirements

Outcomes served: system described, requirements defined.

| Subject | What the agent does |
|---|---|
| Software requirements | shall establish, prioritize and record in the software requirements specification, for each software element or configuration item, its functional and non-functional requirements and its interfaces, the specifications of quality characteristics included, and define the derived requirements |
| Quality model | should specify the quality characteristics of the software under a quality model |

The requirements for a software element shall cover the content of the table below.

| Subject | Content |
|---|---|
| Functions | the functions and capabilities, performance and physical characteristics and the environmental conditions of use included |
| Interfaces | the external interfaces |
| Qualification | the qualification requirements |
| Safety | the methods of operation and support, the environmental influences and the harm to personnel |
| Security | the threats to sensitive information |
| Ergonomics | manual operations, human-equipment interaction, the constraints on personnel, and the areas that need concentrated attention and are sensitive to human error and training |
| Data | the data description and the database requirements |
| Installation and acceptance | the installation and the acceptance of the delivered product at the operation and maintenance sites |
| User documentation | the requirements for user documentation |
| User operations | the user operations and their execution |
| User maintenance | the user maintenance requirements |

## Analysing system requirements

Outcomes served: requirements analysed.

| Subject | What the agent does |
|---|---|
| Evaluation | shall analyse the software requirements for correctness, completeness, consistency, feasibility and testability, evaluate them against their traceability to the system requirements and the system design, their external consistency with the system requirements, their internal consistency, their testability, the feasibility of the software design and the feasibility of operation and maintenance, and record the results |
| Reviews | shall have the software requirements pass the technical review, which the verification process conducts, and the management review, which the project assessment and control process conducts |
