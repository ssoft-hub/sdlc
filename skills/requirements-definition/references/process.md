# The system/software requirements definition process

| Name | Statement | Observable as |
|---|---|---|
| purpose | the stakeholders' user-oriented view of the required capabilities is transformed into a technical view of a solution that meets the users' operational needs: a set of measurable system requirements that specify, from the supplier's perspective, the characteristics, attributes, functional and performance capabilities the system is to possess to satisfy the stakeholder requirements, the stakeholder requirements transformed into the system technical requirements that guide its design, and the requirements for the software elements of the system established; as far as the constraints allow, the requirements dictate no specific implementation | - |
| system described | the description of the system for system solutions - its interfaces, functions and boundaries - is defined, the requirements for its software elements and their interfaces included | the functional boundary, the functions and the interfaces of the system and of each software element recorded |
| requirements defined | the system requirements - functional, performance, process, non-functional and interface - and the design constraints are defined, describing the problem to be solved; the requirements, with the priorities of implementing the software requirements, are accepted, updated as needed, included in a baseline and communicated to all parties involved | the requirements specification recorded with the rationale of each requirement, and its baseline with the record of its communication |
| measures defined | critical performance measures are defined | the measures recorded with the measures of effectiveness they derive from |
| requirements analysed | the system and software requirements are analysed for correctness and testability, their impact on the operational environment is understood, appropriate techniques optimize the preferred design solution, and changes to the baseline are evaluated for cost, schedule and technical impact | the results of the analysis and of each evaluation of a change recorded |
| enabling inputs defined | the inputs for the requirements for any enabling systems or system elements the definition needs are defined | the inputs for the requirements for the enabling systems defined |
| enabling systems available | the enabling systems and services the definition needs are available | access obtained to each enabling system and service the definition uses |
| traceability established | traceability and consistency are established between the system requirements and the baseline of the stakeholder requirements, and between the software requirements and the system requirements | each system requirement traced to a stakeholder requirement, and each software requirement to a system requirement |
