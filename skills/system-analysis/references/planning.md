# Planning system analysis

## Acts of this situation

| Act | An explicit request does not decide it while | Tasks still due on an explicit request |
|---|---|---|
| acquiring access to an enabling system, a model or data that costs money or binds the project by conditions | - | Access |
| an experiment that loads or changes a system in operation or resources the project shares | - | Consequences; Assumptions and Record of `SKILL.md`, for the experiment |

## Preparing for system analysis

Outcomes served: studies identified, inputs identified, enabling systems available.

| Subject | What the agent does |
|---|---|
| Strategy | shall define the system analysis strategy |
| Its decision | should present a strategy it has defined with the output of the work for a decision |
| Enabling systems | shall identify and plan the enabling systems and services the analysis needs - tools, models, data stores |
| Inputs for requirements | shall identify and record the inputs for the requirements on the enabling systems and on the system elements the analysis needs, such as a prototype of an element |
| Their requirements | should define the requirements for the enabling systems and the interfaces with them |
| Tools | should select the tools to suit the methods selected |
| Models and data | should determine the suitability of the models and the data |
| Access | shall obtain or acquire access to the enabling systems and services to be used |
| Validation | should have the validation process confirm objectively that an enabling system - a model or a tool - achieves its intended use |
| Consequences | shall name, before an experiment on a system in operation, its known consequences for the services and the data |
