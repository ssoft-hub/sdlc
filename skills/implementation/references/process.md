# The implementation process

| Name | Statement | Observable as |
|---|---|---|
| purpose | a specified system element is realized - for software, a software item and its executable software units that reflect the design are produced; the requirements, the architecture and the design, the interfaces included, are transformed into actions that, with the technology selected, create an element satisfying the system requirements, the allocated and derived ones included, the architecture and the design | - |
| constraints identified | the implementation constraints that influence the requirements, the architecture or the design are identified | the constraints recorded and passed to the system/software requirements definition, architecture definition and design definition processes; a defect of an accepted output recorded with its change request |
| element implemented | a system element is implemented | the units and databases recorded with their unit test procedures, data and results, the evaluation of the code, and the objective evidence that the element satisfies the system requirements |
| element packaged or stored | a system element is packaged or stored | the element packaged and stored under the agreement on its delivery, its implemented baseline under configuration management |
| enabling inputs identified | the inputs for the requirements for the enabling systems or system elements that serve the implementation are identified | the enabling systems planned and the inputs for their requirements identified |
| enabling systems available | the enabling systems or services the implementation needs are available | access obtained to each enabling system planned |
| traceability established | traceability of the implemented elements is established | the traceability record between the units, the requirements and the design |
