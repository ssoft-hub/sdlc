# Configuration status accounting

## Configuration status accounting

Outcomes served: status maintained.

| Subject | What the agent does |
|---|---|
| Status information | shall develop and maintain the configuration status information of the elements, the baselines and the releases at an acceptable level of integrity and security, its records and reports showing the status and the history of the managed elements, the baseline included, and how the elements relate in the current integration |
| Data | shall collect, store and report the configuration management data, and make the changes and the releases available to the stakeholders |
| Use of the information | should make the status information give the data for decisions on the elements throughout the life cycle, and forward and backward traceability to the other states of the configuration |
| Rationale | should record the rationale of the baselines, the releases and the authorizations |
| Keeping | should keep the records throughout the life cycle and then archive them as the agreements, the legislation or best practice require |
| Current and previous states | should manage the records, the retrieval and the consolidation of the data of the current and of every previous state of the configuration so that their correctness, timeliness, integrity and security can be confirmed |
| Status report | should name in the status report the number of changes to the project, the latest versions of the software items, the release identifiers and numbers, and a comparison of the releases, such as a changelog or release notes |
