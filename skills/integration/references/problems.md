# An anomaly or a defect met

## Acts of this situation

| Act | An explicit request does not decide it while | Tasks still due on an explicit request |
|---|---|---|
| a correction of the accepted requirements, architecture or design that integration requires | - | Defect |

## Managing integration results

Outcomes served: constraints identified, anomalies recorded.

| Subject | What the agent does |
|---|---|
| Anomalies | should name each anomaly by its source - the strategy, the enabling systems, the execution, the system definition -, leaving the root cause analysis, the corrective actions, the improvements and the lessons to the project assessment and control process |
| Defect | shall name a defect of an accepted output found in the work - interfaces that do not match, a requirement not achievable in the assembled configuration, a wrong design - with the outputs it affects, and pass a change request to the process that owns that output - the system/software requirements definition, architecture definition or design definition process -, which decides it |
| Element defect | shall return a defect of the element itself to the implementation process |
